# MAVEB Research Oracles

Research oracles are offline kill-tests. They answer whether a more complicated runtime idea is worth implementing before the project commits to it.

## Current CBRC oracle

The active MAVEB-CLOSURE paper line uses an **independent full-reference Gaussian replay oracle** to test emitted certificates.

A certified result must satisfy:

```
measured_full_reference_error <= certified_bound <= epsilon
```

The production certificate and the full-reference measurement are generated by separate paths and their provenance is preserved in the evidence bundle.

See:

- `tools/maveb-cbrc-gaussian-oracle/`
- `benchmarks/scripts/cbrc_replay.py`
- `benchmarks/scripts/cbrc_evidence_bundle.py`

## Deferred representation-migration oracle

The temporal representation oracle in this directory is a **follow-up kill-test**, not part of the CBRC v1 headline claim.

MAVEB must not build an online TSDF↔mesh↔Gaussian migration policy until measured offline data shows that temporal representation switching can beat the best fixed representation.

For every stable region and revision, collect real measurements for each feasible representation:

- geometry error;
- render error;
- retained memory;
- render milliseconds;
- update milliseconds;
- migration cost from the previous representation.

Compare:

1. best fixed representation for the whole sequence;
2. fixed hybrid rule;
3. per-revision offline oracle;
4. only if (3) dominates, a later online causal policy.

If the offline oracle cannot materially Pareto-dominate the best fixed strategy, kill temporal migration before writing runtime code.

This separation keeps deferred research from being mistaken for unfinished CBRC v1 implementation.
